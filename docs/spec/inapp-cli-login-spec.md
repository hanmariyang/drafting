# 인앱 CLI 구독 로그인 (설계 노트)

> 결정: **설계 노트만**(2안). 구현은 보류. 앱에서 `claude /login` 을 유도해 구독 인증을 앱 컨텍스트에 묶는다.

## 배경 — 왜 필요한가

CLI(구독) 모드는 claude OAuth 토큰을 **macOS 로그인 키체인**에서 읽는다. claude 가 (npm/네이티브 설치라) 미서명이면
접근 때마다 키체인 확인이 필요한데, Drafting.app 이 백그라운드로 스폰한 claude 는 그 확인 창을 못 띄워 조용히 거부
→ "OAuth session expired". 특히 **정식 인스톨러가 아닌 파일 복사 설치**(미서명·격리)면 더 잘 막힌다.

## 아이디어

앱 안에서 로그인을 **유도**하면, 그때 뜨는 키체인 허용 프롬프트를 사용자가 "항상 허용"으로 승인 →
이후 앱 컨텍스트의 claude 읽기가 통과할 수 있다.

## 구현 스케치

- `claude /login` 은 대화형 TUI + 브라우저 OAuth(로컬 콜백)라 stdio 파이프로는 안 됨 → **PTY(node-pty)** 필요.
  - desktop 데몬에 node-pty 추가(coxpit-oss 계보 재사용), 앱 안 작은 터미널 위젯에 스트리밍.
  - 로그인 명령을 PTY 로 스폰 → 브라우저 열림 → 사용자 인증 → claude 로컬 콜백 수신 → 저장.
  - 성공 후 `verifyCliAccess` 재검증 → CLI 모드 활성.
- 엔드포인트: `POST /api/settings/cli/login/start`(PTY 세션 시작) + WS 스트림 + `.../login/status`.

## ⚠️ 한계 (반드시 명시)

문제 뿌리가 **앱 서명/격리**면, 인앱 로그인의 키체인 **쓰기**가 거부되거나 써진 항목을 나중에 못 읽을 수 있다.
→ "될 수도, 안 될 수도". 이 케이스의 확실한 정답은 **정식(공증) 인스톨러 재설치**.
따라서 인앱 로그인은 "이 버그 해결책"이 아니라 **정상 설치 사용자의 온보딩 편의**로 자리매김한다.

## 대안 (지금 권장)

- **BYOK(허용 모델 선택)** — 키체인과 무관, 즉효(v1.1.1 게이트웨이 기본 모델 이후 더 매끄러움).
- **정식 인스톨러 재설치** — CLI 모드를 살리는 확실한 길.
