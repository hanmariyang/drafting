# P-02 — UX 모드 전환 최소화 (Interview → Draft → Editor)

> "신발 세 번 갈아신기" 문제: 인터뷰 → 스트리밍 뷰어 → 편집기의 세 화면 전환을 없앤다.
> **핵심 원칙: 스트리밍 완료 즉시 편집기 활성. "초안 전용 뷰어" 화면을 별도로 두지 않는다 (G-05).**

## 1. 단일 워크스페이스 화면

문서 작업은 **하나의 화면(DocumentWorkspace)** 안에서 상태만 바뀐다. 라우팅은 `/projects/:pid/documents/:did` 단 하나.

```
┌──────────────────────────────────────────────────────────────────┐
│  DocumentWorkspace  (한 화면, 상태만 전이)                          │
│                                                                    │
│  ┌───────────────┐   ┌──────────────────────────────────────────┐ │
│  │  좌: 인터뷰    │   │  우: 문서 캔버스 (에디터 + 미리보기)        │ │
│  │  패널          │   │                                          │ │
│  │  (챗 인터뷰)   │   │  섹션들이 스트리밍되며 채워지고,           │ │
│  │               │   │  완료된 섹션은 즉시 편집 가능              │ │
│  │  진행바        │   │                                          │ │
│  └───────────────┘   └──────────────────────────────────────────┘ │
│                                                                    │
│  좌측 패널은 접을 수 있음(collapse). 편집에 집중하면 접는다.         │
└──────────────────────────────────────────────────────────────────┘
```

인터뷰 패널과 캔버스는 **동시에 존재**한다. "화면을 넘어간다"가 아니라 "좌측 패널의 역할이 바뀐다".

## 2. 화면 상태 전환 다이어그램

한 화면 안의 상태 머신. `phase` 는 **캔버스의 편집 활성도**만 바꾼다.

```
        ┌──────────────┐
        │  INTERVIEWING │  좌: 질문/답변 진행. 우: 빈 캔버스(플레이스홀더)
        └──────┬───────┘
               │ 마지막 답변 제출 → "초안 생성" 트리거
               ▼
        ┌──────────────┐
        │  STREAMING    │  우: 섹션이 위→아래로 스트리밍.
        │               │  ✔ 이미 완료된 섹션은 그 즉시 편집 가능(editable=true)
        │               │  ✔ 스트리밍 중인 섹션만 read-only(커서 대기)
        │               │  좌: 진행률 + "재생성"은 완료 섹션에 한해 노출
        └──────┬───────┘
               │ 마지막 섹션 스트리밍 완료
               ▼  (별도 화면 전환 없음 — 같은 캔버스)
        ┌──────────────┐
        │  EDITING      │  우: 전 섹션 편집 가능 + 분할 미리보기(SPEC-08)
        │               │  좌: 인터뷰 패널 접힘/요약. 섹션 재생성·추가 가능
        └──────┬───────┘
               │ (사용자가 다시 인터뷰 열기 / 섹션 재생성)
               └──────────▶ STREAMING (해당 섹션만) ──▶ EDITING
```

### 상태별 캔버스 규칙

| phase | 완료 섹션 | 진행 중 섹션 | 미리보기 |
|-------|----------|-------------|---------|
| INTERVIEWING | — (없음) | — | 플레이스홀더 |
| STREAMING | **편집 가능** | read-only(스트리밍 커서) | 실시간 반영 |
| EDITING | 편집 가능 | — | 동기 스크롤(SPEC-08) |

## 3. "완료 섹션 즉시 편집" 구현 계약

- 초안 스트리밍은 **섹션 경계 이벤트**를 보낸다(SSE): `section_start` → `token`* → `section_end`.
- 프론트는 `section_end` 를 받는 즉시 해당 섹션의 `editable=true` 로 전환. 다음 섹션 스트리밍을 기다리지 않는다.
- 사용자가 완료 섹션을 편집하는 동안에도 다음 섹션 스트리밍은 계속된다(비차단).
- 편집 중이던 섹션에는 스트리밍이 절대 다시 쓰지 않는다(섹션 id 로 타겟팅, 진행 커서는 아직 안 끝난 섹션에만).

SSE 이벤트 스키마:

```
event: section_start   data: {"sectionId":"s1","heading":"개요","index":0,"total":6}
event: token           data: {"sectionId":"s1","delta":"이 제품은 "}
event: section_end     data: {"sectionId":"s1"}          ← 프론트: s1 editable=true
...
event: done            data: {"documentId":"d1"}         ← phase = EDITING (전환 아님, 승격)
event: error           data: {"message":"..."}
```

## 4. 수용 기준 매핑

- 스트리밍 중 완료된 섹션 즉시 편집 가능 — 전용 뷰어 화면 없음 (Phase 1 검증 항목).
- 라우트는 단일(`/projects/:pid/documents/:did`). "뷰어 전용" URL·컴포넌트 부재로 정적 확인.
- PRD 1건: 인터뷰 시작 → 스트리밍 완료 → 편집기 진입까지 화면 이동 0회, ≤ 30분.
