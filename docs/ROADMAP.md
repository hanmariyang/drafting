# Drafting 로드맵 — → v1.0.0

**1.0 의 정의**: 인터뷰 → 문서 체인(PRD·기능명세·IA·유저플로우) → 핸드오프가 **어떤 provider(구독·BYOK·OpenAI 호환 게이트웨이)에서도 안정적으로** 돌고, 산출물을 실무로 바로 내보낼 수 있는 상태. 목표 지표: "기획 1건을 인터뷰에서 개발 지시서까지 30분."

현재: **v0.4.7** — 핵심 흐름·산출물 스위트·정합성(위반 근본 해소 편집기 포함)·BYOK/구독/게이트웨이·내보내기·공유·데스크톱/도커/릴리스 CI 완료.

## v0.5 — 안정화 & 신뢰 (Reliability)
1.0 의 토대는 신뢰. 실사용에서 드러난 문제부터.
- **추론형 모델 대응** — reasoning 모델은 토큰 예산이 작으면 본문이 빈칸으로 나온다. 기본 예산 상향 + 빈 본문 감지·경고, 스트리밍에 "생각 중" 표시.
- **provider 에러 표준화** — 401/403/모델 권한/게이트 요구/게이트웨이 오류를 사용자 언어 + 해결 힌트로 매핑, 재시도.
- **빈 상태·경계 케이스 총점검** — 위반만 있는 문서, 생성 중 취소, 네트워크 끊김, 빈 인터뷰.
- **교차 문서 표시 정합** — 구조 뷰는 자기 문서 항목만 로드하므로, 다른 문서 데이터에 의존하는
  표시(IA '도달 플로우', 화면↔기능 등)는 반드시 해당 문서를 명시적으로 로드해야 한다. 서버 lint
  판정과 클라이언트 표시가 어긋나지 않도록 전 구조 뷰 점검. (IA '도달 플로우 없음' 오표시 수정, v0.6.2)
- **데이터 안전** — 워크스페이스 전체 백업/복원(DB export/import), 스키마 마이그레이션 정착.

## v0.6 — 문서 체인 완성도 (Chain quality)
- **연결 편집기 일반화** — 기능↔요구(REQ)·화면↔기능·화면↔플로우까지(현재 기능↔플로우만) → 모든 링크 위반을 UI 로 근본 해소.
- **프로젝트 허브** — 체인 전체 상태 한눈에(문서별 수락률·위반·stale) + "다음 할 일" 안내.
- **stale 전파 UX** — 무엇이 왜 stale 인지, 부분 재생성.
- 링크 그래프 시각화(요구→기능→화면→플로우).

### ⭐ 다음 마일스톤 — 디자인 시스템 인터뷰 (v1.2 착수 예정)

시안의 목적을 "컴포넌트 그리기"에서 **"그 제품의 디자인 시스템을 설계하기"**로 끌어올린다.
지금 StyleGuide(프리셋)를 **인터뷰로 설계하는 디자인 시스템**으로 승격. 결정: **신규 `design-system` 문서 타입**.

- 체인: `PRD → 기능명세 → IA → 유저플로우 → 디자인 시스템 → 와이어프레임/시안`.
- **P1 (먼저 구현)** — `design-system` 문서 타입 + 인터뷰 7문(성격·레퍼런스·맥락·색·타이포·형태·접근성) +
  구조 생성 → **DesignSystem 토큰**(색 역할·타이포·간격·형태·톤, StyleGuide 상위집합, 제안→수락) +
  **스타일 타일 프리뷰**(스와치·타입 스펙·컴포넌트 샘플) + 와이어프레임/시안이 그 StyleGuide 소비. 프리셋=시드 유지.
- **P2** — AI 가 2~3개 시스템 **방향안**을 제시해 고르기(디자인 탐색).
- 설계: `Docs/spec/design-system-interview-spec.md`

### 🔴 시급 (버그·실사용 차단)

- **[버그] 무거운 화면 AI 시안 생성 실패** — 기능을 많이(예: 8개) 몰아넣은 화면은 응답이 길어져
  CLI `--max-turns 1`/토큰 한계에 확률적 실패(빈/잘린 HTML). 기능 적은 화면은 정상.
  후보: 시안 전용 maxTokens 상향 + `--max-turns` 여유 · 미완성(닫는 `</html>` 없음) 감지→자동 재시도 · 큰 화면 섹션 분할.

### 🧩 기능 백로그

- **프로젝트 완전 내보내기·가져오기 (스냅샷 이동)** — 전체 상태 무손실 `.drafting` 번들(문서 체인·항목·제안 상태·
  근거/링크·섹션·이력·설정) export/import. 계정·서버 없이 기기 간 작업 이동(로컬-퍼스트, 멀티 디바이스의 실용 대안).
  ⚠️ BYOK 키는 번들 제외. 라운드트립 1:1 재현이 핵심.
- **인앱 CLI 구독 로그인 (PTY 온보딩)** — 앱에서 `claude /login` 을 유사터미널(node-pty)로 유도(coxpit-oss 계보).
  ⚠️ 미서명/격리 설치의 키체인 거부까지 고친다는 보장은 없음(정식 인스톨러가 그 케이스의 정답) → 일반 온보딩 편의로. 설계 노트만.
- **시안 외부 확장 (D · 다운스트림 위임)** — 구조/시안 스펙을 v0·피그마·코딩 에이전트로 내보내 고급 시안/코드 생성.
  Drafting 은 기획·구조 SSOT 로. (설계: `Docs/spec/wireframe-mockup-spec.md`)
